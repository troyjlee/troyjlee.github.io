Longest Common Substring

Longest Common Substring

In the longest common substring (LCStr) problem we are given two strings, say “pineapple” and “grappled”.

The goal is to find the length of a longest string that occurs as a substring in both input strings.

In this case the answer would be 5. The longest common substring is “apple”.

Subproblems

Our first task in the DP strategy is to define useful subproblems.

In previous examples, subproblems were based on prefixes of the input.

Now we have two inputs, call them $a$ and $b$. Let’s consider subproblems based on a prefix of $a$ and a prefix of $b$.

2D DP Table

Indices start at $0$. Write $a[0..i]$ for the prefix $a[0], \ldots, a[i]$, so $a[0..m-1]$ is all of $a$.

Define a subproblem on the prefixes $a[0..i]$ and $b[0..j]$, and let $\mathtt{dp}[i][j]$ be its answer.

Intuitively, we will use $\mathtt{dp}[k][\ell]$ for $k < i, \ell < j$ to solve $\mathtt{dp}[i][j]$.

We can solve the subproblems row-by-row from top to bottom and respect the prerequisites.

First Attempt

First attempt: what is the longest common substring on these prefixes?

In this example, the longest common substring on the highlighted prefixes is ‘a’.

Careful Knowing this does not seem helpful for the next subproblem, as this common substring cannot be continued in “grappled”.

Second Attempt

Second attempt: what is the longest common substring on these prefixes that ends at $i$ in $a$ and at $j$ in $b$?

On the highlighted prefixes the answer is now 0: no common substring ends with ‘a’ in one string and ‘p’ in the other.

With this definition we can relate $\mathtt{dp}[i-1][j-1]$ to $\mathtt{dp}[i][j]$.

Second Attempt

When the last characters match, a common substring ending at $(i-1, j-1)$ extends by one letter.

Here ‘a’, then ‘ap’, then ‘app’ build up along the diagonal: $1, 2, 3$.

The LCStr Recurrence

Let $\mathtt{dp}[i][j]$ be the length of a longest substring ending at index $i$ in $a$ and index $j$ in $b$.

The LCStr Recurrence

Recurrence
$$\mathtt{dp}[i][j] = \begin{cases} 0 & \text{if } i < 0 \text{ or } j < 0\\[2pt] 0 & \text{if } a[i] \ne b[j]\\[2pt] 1 + \mathtt{dp}[i-1][j-1] & \text{otherwise} \end{cases}$$

The final answer is the maximum entry anywhere in the table.

Longest Common Subsequence

Longest Common Subsequence

In the longest common subsequence (LCS) problem we are given two strings, say “spaceheater” and “sheeptractor”.

The goal is to find the length of a longest string that occurs as a subsequence in both input strings.

In our example, “spactr” is a subsequence of both inputs, as is “sheatr”.

These realize the maximum length of an LCS, which is 6.

Subproblems

We again consider subproblems defined on prefixes of the two inputs.

As in other subsequence problems, a good subproblem definition is the original problem on these prefixes.

Definition Let $\mathtt{dp}[i][j]$ be the length of a longest common subsequence of $a[0..i],\, b[0..j]$.

Base Case

Let $\mathtt{dp}[i][j]$ be the length of a longest common subsequence of $a[0..i],\, b[0..j]$.

Base case If $i < 0$ or $j < 0$ then $\mathtt{dp}[i][j] = 0$.

The longest common subsequence of any string with the empty string is 0.

Update: $a[i] \ne b[j]$

We condition on whether or not $a[i] = b[j]$.

If $a[i] \ne b[j]$ then the last element of an LCS of $a[0..i],\, b[0..j]$ is either not $a[i]$, or not $b[j]$, or neither.

Thus the LCS of $a[0..i],\, b[0..j]$ is either an LCS of $a[0..i-1],\, b[0..j]$ or of $a[0..i],\, b[0..j-1]$.

Update $$\mathtt{dp}[i][j] = \max(\mathtt{dp}[i][j-1],\, \mathtt{dp}[i-1][j])$$

Update: $a[i] = b[j]$

Now suppose $a[i] = b[j]$.

We can extend the LCS of $a[0..i-1],\, b[0..j-1]$ with $a[i] = b[j]$.

Update
$$\begin{aligned}\mathtt{dp}[i][j] = \max(&1 + \mathtt{dp}[i-1][j-1],\\[2pt] &\mathtt{dp}[i][j-1],\, \mathtt{dp}[i-1][j])\end{aligned}$$

We can further simplify this case.

Simplifying the Match Case

Case $a[i] = b[j]$:

Note that $\mathtt{dp}[i][j-1],\, \mathtt{dp}[i-1][j]$ each exceed $\mathtt{dp}[i-1][j-1]$ by at most one, thus

$$1 + \mathtt{dp}[i-1][j-1] \ge \max(\mathtt{dp}[i][j-1],\, \mathtt{dp}[i-1][j])$$

Update
$$\mathtt{dp}[i][j] = 1 + \mathtt{dp}[i-1][j-1] \qquad \text{when } a[i] = b[j]$$

Final Update

Recurrence
$$\mathtt{dp}[i][j] = \begin{cases} 0 & \text{if } i < 0 \text{ or } j < 0\\[2pt] 1 + \mathtt{dp}[i-1][j-1] & a[i] = b[j]\\[2pt] \max(\mathtt{dp}[i][j-1],\, \mathtt{dp}[i-1][j]) & \text{otherwise} \end{cases}$$

The length of an LCS is $\mathtt{dp}[m-1][n-1]$, the bottom-right cell — unlike LCStr, where we took the maximum over the whole table.

Final Update

Recurrence
$$\mathtt{dp}[i][j] = \begin{cases} 0 & \text{if } i < 0 \text{ or } j < 0\\[2pt] 1 + \mathtt{dp}[i-1][j-1] & a[i] = b[j]\\[2pt] \max(\mathtt{dp}[i][j-1],\, \mathtt{dp}[i-1][j]) & \text{otherwise} \end{cases}$$

For strings of length $m$ and $n$ this finds the length of an LCS in time $O(mn)$.

We have reasons to think this algorithm is essentially optimal (discussed later).

Traceback: Recovering the LCS

The table gives the length of an LCS. To recover the LCS itself, walk backwards from $\mathtt{dp}[m-1][n-1]$:

  • If $a[i] = b[j]$, this character is part of the LCS: output it and step diagonally to $(i-1, j-1)$.
  • Otherwise step to whichever of $(i-1, j)$ and $(i, j-1)$ holds the larger value — that is where the max came from.
  • Stop when $i < 0$ or $j < 0$; the output, reversed, is an LCS.

Traceback in Code

while i ≥ 0 and j ≥ 0:
    if a[i] == b[j]:            # match: part of the LCS
        out.push_back(a[i]); --i; --j
    else if dp(i-1, j) ≥ dp(i, j-1):
        --i                     # LCS unchanged without a[i]
    else:
        --j                     # LCS unchanged without b[j]
reverse(out)

The walk takes $O(m + n)$ steps.

LIS and LCS

LIS and LCS

Do you think LIS and LCS have anything to do with each other?

We can use an algorithm for LIS to solve LCS.

Let’s look at the reduction with an example.

Reduction

For every letter in $x$, write down the positions it appears in $y$ in decreasing order.

Form a list of numbers $z$ by replacing each character of $x$ with this list of positions.

Reduction

Question 1: what is the size of $z$?

Size of $z$

Let $r_i$ be the number of times $x[i]$ appears in $y$.

Then the size of $z$ is $$r = \sum_{i=0}^{m-1} r_i$$

Size of Input

The size of $z$ can range from $0$ (the two strings are disjoint) to $mn$.

Size of Input

The size of $z$ can range from $0$ (the two strings are disjoint) to $mn$.

In the situation of comparing files with diff, we typically don’t expect a line of one file to appear many times in the other file.

If each line of the first file appears a constant number of times in the second then the size of $z$ is $O(m)$.

Building $z$

Question 2: how much time does it take to make $z$?

  • Put the elements of $x$ into a map with value an empty list — $O(m \log m)$.
  • Iterate through $y$. If $y[i]$ is in the map, add $i$ to the list associated with $y[i]$ — $O(n \log m)$.
  • Iterate through $x$ to build $z$ — $O(m \log m + r)$.

Correctness

Correctness

Claim Any increasing sequence in $z$ corresponds to a common subsequence of $x$ and $y$, and vice versa.

The decreasing order within each letter’s block matters: an increasing sequence can use at most one number per block, so each letter of $x$ is matched at most once.

A LIS of $z$ is a longest common subsequence of $x$ and $y$.

Summary

We can find the LCS of $x$ and $y$ by a reduction to LIS in time

$$O(m \log m + n \log m + r \log m)$$

The last term is the LIS on $z$: patience sorting keeps one pile per unit of LIS length, and that length is at most $m$, so each of the $r$ insertions costs $O(\log m)$.

In applications where $r$ is $O(m + n)$ this can be much better than the $\Theta(mn)$ time algorithm we saw previously.

In Practice: diff

Takeaway This is how the original Unix diff compared files (Hunt–Szymanski, 1976): lines rarely repeat, so $r$ is small and LCS-via-LIS runs in near-linear time.

Modern tools took a different route — git diff defaults to Myers’ $O(ND)$ algorithm — though git diff --patience still finds an LIS over uniquely-matching lines.

Fine-Grained Complexity

Satisfiability

Probably the most famous problem in theoretical computer science.

In the SAT problem the input is a formula that is an AND of ORs of variables and their negations.

$$(x_3 \vee x_2 \vee x_4) \wedge (\neg x_4 \vee x_1 \vee \neg x_2) \wedge (\neg x_3 \vee \neg x_4 \vee \neg x_1)$$

Is there a Boolean assignment to the variables that makes the formula true?

In this example, the assignment $x_1 = 1, x_2 = 0, x_3 = 1, x_4 = 0$ works.

3-SAT

$$(x_3 \vee x_2 \vee x_4) \wedge (\neg x_4 \vee x_1 \vee \neg x_2) \wedge (\neg x_3 \vee \neg x_4 \vee \neg x_1)$$

This is an example of a 3-SAT formula because each OR clause involves 3 variables or their negations.

We don’t believe that it is possible to solve every 3-SAT formula on $n$ variables in time polynomial in $n$.

Whether this is possible is equivalent to the question of whether P is equal to NP.

Algorithms for 3-SAT

The trivial algorithm for 3-SAT takes time $\mathrm{poly}(n)\, 2^n$: try all $2^n$ possible assignments and see if any of them work.

We can beat brute force: PPSZ solves 3-SAT in randomised time $O(1.308^n) = O(2^{0.388 n})$.

Paturi, Pudlák, Saks and Zane, “An Improved Exponential-Time Algorithm for $k$-SAT”; analysis for general 3-SAT due to Hertli.

After a lot of effort, however, we don’t know of any algorithms faster than exponential time $2^{cn}$.

Exponential Time Hypothesis

Impagliazzo and Paturi formalized this barrier in the exponential time hypothesis.

ETH There is a constant $c > 0$ such that solving 3-SAT requires time $\Omega(2^{cn})$.

This is a much stronger statement than $\mathsf{P} \ne \mathsf{NP}$.

Impagliazzo and Paturi, “On the Complexity of $k$-SAT”.

Strong Exponential Time Hypothesis

In $k$-SAT we allow the ORs of $k$ variables or their negations.

The larger $k$ is, the harder the problem becomes.

SETH For every $\varepsilon > 0$ there is a $k$ such that solving $k$-SAT requires time at least $2^{(1-\varepsilon)n}$.

Back to LCS

Theorem If there exists $\varepsilon > 0$ such that for any two strings $x, y$ of size $n$ we can compute the length of an LCS of $x$ and $y$ in time $O(n^{2 - \varepsilon})$, then SETH is false.

A relatively small speedup to the basic DP solution for LCS would also imply a breakthrough in algorithms for SAT.

Abboud, Backurs and Vassilevska Williams, “Tight Hardness Results for LCS and Other Sequence Similarity Measures”; Bringmann and Künnemann, “Quadratic Conditional Lower Bounds for String Problems and Dynamic Time Warping”.

Connections

SAT and LCS are both extremely well studied problems of practical interest.

Why is SETH a more compelling hypothesis than that the DP algorithm for LCS is optimal?

The real value here is the connection between problems: we are stuck in finding better algorithms for LCS for the same reason as in SAT.
